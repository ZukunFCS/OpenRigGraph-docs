Maya integration contracts
==========================

Load a plug-in compiled for the actual Maya ABI before creating ORG nodes or
opening a scene containing them. The node pages list registered attributes from
the current source snapshot. All integration nodes are separate from portable
Graph IR type names. Creation alone does not prepare required data or verify
deformation.

Packed layouts and typed boundaries
-----------------------------------

Graph controller and output orders define numeric array indices. XYZ points
use three values; matrices use sixteen row-major values. Distinguish packed
graph outputs, deformation points, influence matrices, and mesh objects. Never
connect buffers based only on their shared double-array storage type.

Input bundles preserve graph defaults and logical indices. Matrix inputs declare
their controller base indices. Matrix scatter input modes distinguish matrix
blocks from other supported transform layouts; preserve the mode and expected
value count generated by the SDK wiring helper.

Scalar scatter selects number, angle, distance, boolean, and integer output
groups using corresponding index arrays. Packed angles are degrees and packed
distances are centimeters; the node produces Maya typed plugs. Boolean values
must be 0 or 1 and integer lanes must contain integral int32 values. Invalid
counts/indices/typed values fail compute. Do not add a second unit conversion
after a correctly typed boundary.

Paths and reloads
-----------------

Absolute paths identify explicit resources. A plain relative path resolves
beside the current scene; give the scene its intended filename before the first
demand. ``@package/relative/path`` resolves under ``OPENRIGGRAPH_PACKAGE_ROOT``
when that root is configured. Load the plug-in and establish package roots before
opening delivered scenes. After replacing data at the same path, increment the
node's reloadToken where provided. Package-relative resources must remain inside
the delivered package.

Geometry packages
-----------------

Package loaders validate versions, point counts/ranges, topology, finite values,
and operation-specific fields. SDK producers capture source geometry and write
these layouts; the node does not discover a character automatically.

.. list-table::
   :header-rows: 1

   * - Node
     - Public package contract
     - Main ownership boundary
   * - openRigGraphBlendShapeBatch
     - openriggraph.blendshape_batch.v1
     - Sparse target groups, weight indices, in-betweens, and packed XYZ points.
   * - openRigGraphSoftModBatch
     - openriggraph.softmod_batch.v1
     - Ordered captured regions/weights and geometry/transform spaces.
   * - openRigGraphSkinBatch
     - openriggraph.skin_batch.v1
     - Influence/bind/weight layout, input mesh geometry, optional packed pre-skin points.
   * - openRigGraphUvPinBatch
     - openriggraph.uvpin_batch.v1
     - Captured mesh/UV attachments and packed point/frame layout.
   * - openRigGraphPointMapBatch
     - openriggraph.point_map_batch.v1 / v2
     - Declared mapping, driver/input meshes, matrix/radius data.
   * - openRigGraphFaceGeometryBatch
     - SDK-produced program; direct public package authoring is not specified
     - Ordered geometry program and its declared input/output buffers.

Use matching-version SDK producers, then verify the public node interface and
delivered geometry. Do not guess serialized fields from example scenes. The
public Python blendshape/face APIs expose reusable data contracts where available.

Cache authoring and playback
----------------------------

Keep editable controls/curves. A curve cache is a prepared numeric data stream
with a declared time range, row layout, interpolation policy, and reload token.
Curve-cache interpolation is 0 exact, 1 nearest (default), or 2 linear.
A double-array switch chooses live or cached values; it does not validate cache
freshness. Invalidate after relevant edits, rebuild before cached mode, and test
fractional/out-of-range times using the chosen policy. See the Python cache and
face-mode APIs and the hypothetical playback decision guide.

Validate interfaces with
:download:`check_interfaces.py <../../../examples/maya/check_interfaces.py>`
and verify deformation using :doc:`../porting/tutorial`. Missing resources may
emit compute errors even when DG nodes can be created; those are dependencies,
not successful evaluation.
